# Engine upgrades and editor redesign

## Delivered

- Independent shipped engine revision `toolsuite/engine-version.json` (0.1.15); each new project stores a plain version in `.forge/engine-v` and a file-checksum baseline. App version remains 0.1.14.
- Opening a project with a missing, empty, invalid or older marker recommends an engine upgrade. Newer engines are flagged; downgrade is blocked.
- Upgrade review lists altered paths and requires individual approval for source changed from its baseline, or unknown legacy source. Plans are hash-bound and checked again after backup to detect intervening edits.
- Engine source, the project editor/config and required dependency declarations update. Models, images, sounds, fonts and other imported assets under `src/assets` are not replaced. Game identity/version and custom dependency declarations are retained.
- Existing scenes, animation tracks/bone names, weapons, HUD/menu screens and unknown authored fields are preserved and validated during document migration; invalid authored data stops the upgrade rather than being silently discarded.
- Every affected existing file is backed up under `.forge/backup/<timestamp-id>/files/<relative-path>` with a checksum manifest before any write. Newly created paths are recorded so restore can remove them. Failed writes roll back. Restore validates checksums and creates a safety backup of the current files first. Restore can revert later edits to covered authored documents; the UI explains that.
- New/upgraded projects store authoritative JSON-envelope documents: `.fsp` metadata/index, `.fss` scenes, `.fsa` clips, `.fsw` weapons, `.fsui` HUD/UI screens. Legacy JSON-only projects work until migration. Runtime JSON caches are generated by native Save/Play/Build and project Vite config; document edits override stale caches. Windows associations/double-click launch are deliberately deferred.
- Dedicated Home project launcher at startup; native window maximized. Home omits editing/shipping toolbars, document tabs, Assets and Console. Sidebar navigation replaces top workspace-mode tabs. Open documents have real tabs, close controls and dirty indicators. The brand uses the Forge F/icon mark plus RGE.
- Asset browser has categorized folders/cards with nested media directory navigation and scoped search. Scene lifecycle controls remain in the Scenes folder. Document cards open the matching scene/clip/weapon/UI editor.
- Dedicated Settings dialog: editor-wide themes, recovery/disk/off autosave, interval, automatic update checks. Recovery-only is the safe default. Gameplay volume/sensitivity stays portable project data in Game.
- Public GitHub/electron-updater groundwork: packaged-only stable checks, explicit download, visible errors/progress, saved-work/native-confirmation restart, no installation on normal quit. No embedded GitHub tokens.
- Preview readiness probes are bounded and reject on window close; close resets Play and refocuses the editor. Quit, editor responsiveness and reopen are regression-tested. Current schema already accepts `quit`; the upgrade replaces legacy project code with that schema rather than weakening validation.
- Complete but older dependency trees now produce an actionable mismatch instead of being silently accepted or overwritten. Users refresh dependencies explicitly; this protection avoids destructive automatic changes to user-managed node_modules.

Covers automatic old-project prompt, conflict approval, upgrade → restore → upgrade, content workflows, Settings, Home/chrome, icon/sidebar/document tabs/folders, Quit → responsive editor → reopen Play, live bot combat and rigged hand/finger animation.

The first desktop attempts found stale harness assumptions (Projects now opens Home, old Home controls moved into Settings/Game, document-tab assertions must inspect document tabs rather than their order) and an asynchronous upgrade-plan wait. These tests were changed to exercise the requested interfaces without dropping assertions. Final reruns pass.

## Limits and deferred work

- No installer build, app-version bump, release upload, git commit or push. The existing release installer predates this task and is unchanged.
- Actual network download and install across two installed Forge versions is not verified here; it requires authorized release packaging. `UPDATE.md` explains the exact metadata, upload, signing and installed-release acceptance workflow. Releases that predate this updater need a manual installation of the first updater-enabled build.
- Current Windows releases are unsigned. SmartScreen/publisher signing setup is the owner's responsibility before production distribution.
- Upgrade preservation is validated and backed up, not a promise that arbitrary custom source merges cannot break. Unknown engine changes need explicit replacement approval; automatic source merging is not performed.
- Media folders are navigable but folder rename/move/delete and Windows extension registration are not implemented.
- Browser preview accessibility and Settings were inspected; screenshot capture could not run because the shared browser webview produced no composited frames. Native harness captures the editor viewport, and desktop behavior is verified, but no subjective visual-quality guarantee is claimed.
